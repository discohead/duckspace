## Issue Details

### QA-026: Error messages expose internal to_arrow_ipc() wrapper SQL

- **Severity**: P2
- **Area**: Query Editor / Error Handling
- **Status**: New
- **Reproduction Steps**:
  1. Open a new query tab (Cmd+T)
  2. Type an invalid query: `SELCT typo FROM nonexistent`
  3. Click Execute
- **Expected Behavior**: Error message shows only the user's SQL in the error context
- **Actual Behavior**: Error message includes internal wrapper: `LINE 1: SELECT * FROM to_arrow_ipc((SELCT typo FROM nonexistent)) ^` exposing the `to_arrow_ipc()` implementation detail
- **Screenshot**: `qa-reports/screenshots/06-query-error.png`
- **Suggested Fix**: Strip `SELECT * FROM to_arrow_ipc((...))` wrapping from error messages in the query router or error handler before returning to the renderer. A regex like `/SELECT \* FROM to_arrow_ipc\(\((.*)\)\)/` could extract the inner SQL.
- **Affected Files**: `src/workers/duckdb-connection.ts` or `src/main/query-router.ts`

### QA-027: No minimum window size — sidebar overlaps content at very small sizes

- **Severity**: P2
- **Area**: Responsiveness
- **Status**: New
- **Reproduction Steps**:
  1. Resize the window to 400x300 pixels
- **Expected Behavior**: Either a minimum window size prevents extreme shrinking, or the layout adapts (sidebar collapses or scrolls)
- **Actual Behavior**: The 240px fixed-width sidebar takes more than half the 400px viewport, leaving minimal space for main content. Welcome text and step items are cramped and partially hidden.
- **Screenshot**: `qa-reports/screenshots/03-resize-400x300.png`
- **Suggested Fix**: Set `minWidth: 800` and `minHeight: 500` in the `BrowserWindow` constructor options in `src/main/lifecycle.ts`
- **Affected Files**: `src/main/lifecycle.ts`

### QA-028: Catalog Browser does not show ad-hoc SQL tables

- **Severity**: P4
- **Area**: Catalog Browser
- **Status**: New (by design for 002-local-data-ingestion)
- **Reproduction Steps**:
  1. Open a query tab and execute `CREATE TABLE test_table AS SELECT 1 AS id`
  2. Switch to a Catalog tab
- **Expected Behavior**: The newly created table appears in the catalog
- **Actual Behavior**: Catalog shows "No tables registered. Execute CREATE TABLE or import data." — the CatalogBrowser only reflects Dexie-tracked data sources from the ingestion pipeline, not DuckDB's `information_schema`
- **Suggested Fix**: Future enhancement — the Catalog Browser could query `information_schema.tables` via IPC to show all DuckDB tables, not just ingestion-pipeline sources. The empty state message is also slightly misleading since CREATE TABLE doesn't actually populate the catalog.

### QA-029: Previous results visible while editing query text

- **Severity**: P4
- **Area**: Query Editor / Result Grid
- **Status**: New
- **Reproduction Steps**:
  1. Execute a query that returns results (e.g., `SELECT 1 AS test`)
  2. Clear the textbox and start typing a new query
  3. Observe that the previous results remain visible below
- **Expected Behavior**: Results could optionally clear when the SQL text changes (debatable UX choice)
- **Actual Behavior**: Previous results persist until the next Execute. This is a common pattern in SQL editors and may be intentional, but could confuse users who think the displayed results correspond to the text they're currently editing.
- **Suggested Fix**: Consider adding a subtle visual indicator (e.g., slightly dimmed results or "Results from previous query" label) when the SQL text differs from what produced the displayed results.

## Positive Observations

1. **Query execution pipeline is solid**: The QA-013 preload buffering fix works — results appear immediately without any dropped batches, even for fast queries like `SELECT 1`.
2. **Tab management is robust**: Creating, switching, and closing tabs works flawlessly. Keyboard shortcuts (Cmd+T, Cmd+W) are responsive. The QA-015 mutex prevents duplicate order values.
3. **Error handling is graceful**: Invalid SQL shows a clear error code [E1001] with the parser error message. The app doesn't crash and recovers immediately — the next query executes normally.
4. **Unicode and special characters work perfectly**: Japanese text, emoji, escaped quotes, and NULL values all render correctly in both the query editor and result grid.
5. **Status bar is informative**: The green "DuckDB: ready" indicator with the colored dot provides clear worker health feedback.
6. **Accessibility tree is well-structured**: Proper ARIA roles (tablist, tab, complementary, status, main), labels, and heading hierarchy throughout.
7. **CatalogSidebar empty state is actionable**: The QA-022 fix provides a clickable "Import files" link in the empty state — good UX improvement.
8. **Result grid shows type badges**: Column headers display Arrow type information (Int32, Utf8, Float64, Decimal, Null) which is helpful for data analysis.
9. **Tab state persists across switches**: Switching tabs preserves both the SQL text and query results — no re-execution needed.
10. **Zero console errors**: No uncaught exceptions, no unhandled promise rejections, no unexpected error logs throughout the entire session.
