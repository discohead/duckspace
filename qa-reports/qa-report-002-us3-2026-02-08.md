## Bugs Found

### BUG-001: Error banner leaks across query tabs (Medium)

**Severity:** Medium
**Area:** Tab State Management / QueryEditor
**Steps to Reproduce:**
1. Open Query 1 tab, execute a valid query (10K row generate_series)
2. Create Query 2 tab via + > New Query
3. Type invalid SQL (`SELEC * FORM nonexistent_table`) and execute
4. Error banner `[E1001] Parser Error` appears correctly on Query 2
5. Switch back to Query 1 tab

**Expected:** Query 1 shows its SQL + results with no error banner
**Actual:** Query 1 shows its SQL + results but ALSO displays Query 2's error banner

**Root Cause (suspected):** The error state is stored in shared React state (likely a `useState` in a component that doesn't reset per-tab) rather than being keyed to the active tab ID or stored in the Dexie tab record.

**Screenshot:** `screenshots/qa-reports-screenshots-03-bug-error-leak-across-tabs.png`

**Suggested Fix:** Store error state per-tab in Dexie (alongside SQL text), or key the QueryEditor's error `useState` to the active tab ID so it resets on tab switch.

---

### BUG-002: Query results lost on tab switch (Low)

**Severity:** Low
**Area:** Tab State Persistence / Arrow Data Lifecycle
**Steps to Reproduce:**
1. Execute a query on Query 1 — 10,000 rows render in the Perspective data grid
2. Switch to any other tab (Settings, Catalog, or another Query)
3. Switch back to Query 1

**Expected:** Query results are still visible
**Actual:** Results area shows "Execute a query to see results" — Arrow data is lost. SQL text is preserved (stored in Dexie).

**Note:** This contradicts the previous QA report (2026-02-08 initial) which stated "Tab state persists across switches." The discrepancy may be due to commit `4088a44` introducing the Perspective data grid which handles data differently than the previous ResultGrid, or the previous test may not have switched away to a non-query tab.

**Impact:** Users must re-execute queries after switching tabs. For expensive queries this is significant UX friction.

**Suggested Fix:** Either cache Arrow buffers per-tab, persist result metadata in Dexie for re-fetch, or auto-re-execute the last successful query when a query tab regains focus.

---

### BUG-003: Catalog Browser doesn't show CREATE TABLE results (Low)

**Severity:** Low (Known — same as QA-028 from previous report)
**Steps to Reproduce:**
1. Execute `CREATE TABLE test_data AS SELECT ...` — success message shown
2. Switch to Catalog Browser tab
3. Catalog still shows "No tables registered."

**Status:** Known limitation. Catalog Browser tracks only ingestion-pipeline DataSource entries (Dexie), not raw DuckDB `information_schema` tables. Same as QA-028.

## US3 Code Review (In Lieu of Visual Testing)

Since file import (and therefore SourceDetail/ColumnStats rendering) could not be tested via Playwright MCP, a code review was performed on the US3 implementation:

### SourceDetail Component (`src/renderer/components/SourceDetail.tsx`)
- Correctly receives `dataSourceId` prop and fetches source via `useDataSource()` hook
- Displays metadata: name, status badge (color-coded), format badge, file path, rows, columns, file size, timestamps
- "Compute Stats" button triggers `window.datspace.catalog.getColumnStats()` with tableName parameter for restart recovery
- Auto-computes stats on first view when source is active and no cached stats exist
- Results stored in Dexie `column_statistics` table via transaction
- Loading/error/empty states all handled
- Wired into App.tsx `data_grid` case as 320px right panel

### ColumnStats Component (`src/renderer/components/ColumnStats.tsx`)
- Renders per-column cards with: column name, type badge, row count, null count/percentage, distinct count
- Null percentage bar visualization
- Numeric stats section (min, max, mean, median, stddev, Q25, Q75) — gated on `isNumericType()` check
- Categorical top values with frequency bars and percentage labels
- Handles parameterized types like `DECIMAL(10,2)` via base type extraction

### IPC Chain (getColumnStats)
- Preload: `getColumnStats(dataSourceId, forceRecompute?, tableName?)` → IPC invoke
- Main handler: Resolves tableName from `dataSourceTableMap` or uses provided tableName (restart recovery), calls `computeStats()` on worker
- Worker: `compute_stats` message → DuckDB SUMMARIZE + top-N queries → `compute_stats_complete` response
- Response mapped to `ColumnStatisticsRecord[]` with `columnType` field

### US3 Acceptance Criteria Mapping
| Criteria | Implementation | Verified |
|----------|---------------|----------|
| Each column shows data type, null count, null % | ColumnStats card header + core stats row | Code review |
| Numeric columns show min/max/mean/median/stddev | Gated `numericSection` with `isNumericType()` | Code review |
| Text columns show top 10 frequent values | `topValuesSection` with frequency bars | Code review |
| 10M row table computes within 10s | 60s timeout in computeStats(), async with loading state | Code review |
